# 1. 討論結論與用語
使用者說明：
舊 TriKeySndMemIME 以漢語拼音的第一個英文字母作為單字三碼的第一碼。
同一漢字在不同詞語中可能有不同讀音，稱為多音字；臺灣亦常稱破音字。
單字選最常用讀音作為主音，保留唯一正式三碼。
第二、第三及其後的其他讀音為可選讀音，只存在於指定詞組，
不建立另一組正式的單字三碼。

雙方最後採用簡短名稱「主音／副音」。
繁體、簡體均寫作「主音／副音」，便於兩岸閱讀。
主音 = Primary pronunciation。
副音 = Alternative pronunciation / Non-primary pronunciation。
副音統稱所有非主讀音，不只第二讀音，也包含第三、第四等。
「副音」是本專案定義的簡稱，不宣稱是通行語言學標準術語。
首次出現時寫「副音（非主讀音）」；不可與「輔音／辅音」混淆。

繁體摘要：
每字只有一組主音正式三碼；副音僅在指定詞組內使用。
簡體摘要：
每字只有一组主音正式三码；副音仅在指定词组内使用。
英文設計名稱：
Canonical Character Code + Phrase-only Pronunciation Alias。

# 2. 必須維持的編碼約束
每個收錄漢字恰好有一個 canonical_code，長度固定為三個合法按鍵。
第一碼依主音拼音首字母決定，第二、三碼沿用既有助憶及補碼規則。
本功能不能藉由更換第二、三碼來增加副音單字條目。
拼音首字母不是完整聲母：zh/ch/sh 只取 z/c/s，零聲母如 an 取 a。
內部按鍵統一小寫；畫面可用大寫展示，大小寫不能形成不同編碼。
主音、正式碼不因當前詞語、輸入歷史或個人使用頻率而即時改變。
副音沒有 canonical_code，不能匯出到正式單字三碼索引。
副音只在明確收錄的詞組及字位置生效，不對所有含該字的詞語泛化。
同一詞組可以有多個經確認的讀音變體，須逐筆列出，不做無限制排列組合。
詞組別名可選；停用時不能改變單字查詢結果。
副音不占正式單字碼空間，但詞組碼仍可能與其他詞組或單字碼相撞，
必須分別檢查，不能宣稱詞組也自然無重碼。
若副音生成的按鍵剛好等於其他字的正式碼，不得禁止該正式字輸出；
限制的是「不得以副音碼新增這個多音字」，不是封鎖那組按鍵。

# 3. 主音如何選定與維護
對新資料，優先使用可追溯語料中「每種讀音的出現次數」；
不能只依漢字總字頻，也不能假設字典第一項就是最常用讀音。
既有正式單字碼先視為相容性基準，不能因新增統計而自動重排。
若缺可靠語料，保留既有主音並標為 legacy 或人工確認，
不得捏造頻率，不得把未知頻率寫成已測得的零。
同頻或缺資料時由維護者確認；未確認資料列為 pending，不進正式產物。
頻率排序用 rank 表示：1 為主音，2 以上為副音。
rank 是資料版本中的順序，不是拼音本身的永久 ID。
人工選定與頻率結果不同時記錄原因；正式碼變更須另列遷移清單。
字典只是讀音候選來源，不足以判斷某個詞語的實際讀音。

# 4. 建議資料模型（新增側錄資料，不破壞既有碼表）
以下為未來新增資料契約，不宣稱目前已有這些檔案。
使用 UTF-8、LF、TSV；欄位以真正 Tab 分隔。
空白行與第一個非空白字元為 # 的整行註解忽略；不使用行尾註解。
欄位內禁止 Tab 與換行。載入失敗應報檔名、行號、欄位及原因。

characters.tsv：
char  canonical_code  primary_reading_id  status  source
char 必須為一個 Unicode scalar value；不可用 UTF-8 byte 長度判斷字數。
本版先採單碼點漢字範圍，變體選擇符等序列另報不支援，不可靜默截斷。
canonical_code 以現有碼表為準；每字唯一且正式碼全域碰碼須明確回報。

readings.tsv：
char  reading_id  pinyin  tone  first_key  rank  role  frequency  source  status
reading_id 為該字內穩定 ID，主鍵為 (char, reading_id)。
pinyin 採小寫、無聲調符號；ü 統一寫 v；tone 為 1..5，5 表輕聲。
first_key 必須與專案拼音首字母規則一致。
role 僅允許 primary 或 alt；rank=1 必須 primary，rank>=2 必須 alt。
每字恰好一筆 primary；主音 ID 須存在且對應 canonical_code 第一鍵。
frequency 未知用 NA；已統計則為非負整數，source 指向語料版本。
status 可用 confirmed、legacy、pending；pending 不進正式輸出。
同字同拼音同聲調不得以不同 ID 重複列入。
僅聲調不同而首字母相同的副音仍保留語音資訊，但不多建相同按鍵別名。

phrases.tsv：
phrase_id  text  status  source
phrase_readings.tsv：
phrase_id  variant_id  char_index  reading_id
char_index 採 0 起算的 Unicode scalar 索引，不是 UTF-8 byte offset。
每個讀音變體對詞組每個字都必須有且只有一筆 reading_id；
先從主音展開，再套用明確副音覆寫也可以，但匯出前須驗證完整結果。
reading_id 須屬於 text 在 char_index 的那個字；不得跨字借用 ID。

phrase_aliases.tsv（產生資料）：
phrase_id  variant_id  phrase_code  uses_alt  rule_version
phrase_code 為既有或另外確認的詞組取碼規則之結果，長度不要求三鍵。
禁止直接將「副音首碼＋原第二三碼」塞回單字正式碼表。
uses_alt 由實際讀音判定，不能因按鍵與主音相同便誤判為沒有副音。
同一 phrase_id 與 phrase_code 重複結果合併，但保留來源變體供追蹤。
副音開關關閉時，主音詞組條目仍可使用；不得因按鍵去重丟失其來源身分。

# 5. 教學示例（不是倉庫實際頻率或實際正式碼）
假設「重」主音為 zhong4：
主音 r_zhong4 -> z；副音 r_chong2 -> c。
「重要」中重使用 r_zhong4；「重複」「重新」中重使用 r_chong2。
假設「行」主音 xing2，則「銀行」的行可明確覆寫為 hang2。
假設「樂」主音 le4，則「音樂」的樂可明確覆寫為 yue4。
這些主音只是說明用途，正式資料必須查原碼表及確認來源。
副音可以出現在詞組的第一、第二、第三或任何字位置，
也可在同詞中多次出現；覆寫必須以位置識別，不能只用漢字當索引。
「得」de2/dei3、「地」di4/de5 等即使首字母相同，
仍可能是不同讀音，但不一定導致不同輸入鍵。
先前討論的 Zxx、Cxx、Xxx、Lxx 等均為占位示意，
不得當作正式碼匯入，也不能依此斷言倉庫當前主音。

# 6. 查詢與生成流程（語言無關偽碼）
build_character_index:
    只讀正式單字碼；檢查每字一碼、三鍵長度與碰碼。
    不讀取 alt 生成單字碼。

build_phrase_index:
    對每個 confirmed 詞組讀音變體：
        以 Unicode 字位置確認每個 reading_id；
        取得各位置實際讀音的 first_key；
        交給已確認的 phrase_code_rule 生成詞組碼；
        存入獨立 phrase_index，附來源及 uses_alt。
    不把所有字的所有讀音做笛卡兒積。
    不修改 character_index。

lookup_character(code):
    僅查 character_index，副音開關不影響結果。

lookup_phrase(code, enable_alt):
    查 phrase_index；
    enable_alt=false 時排除僅由副音來源支持的條目；
    按既有詞組候選排序，去除相同詞語重複項。

同一按鍵可同時命中單字及詞組，須由既有輸入狀態／模式處理；
不得僅憑碼長為三就認定單字，詞組碼也可能恰好三鍵。
若未建立明確模式，使用帶 entry_kind 的候選清單呈現衝突，
不能讓詞組覆蓋正式單字或自動送出錯誤結果。
空白送字／分隔操作沿用現有行為，副音功能不得暗中改變。

# 7. 目前倉庫與後續修改定位
本次檢閱 README.md、intro.txt、type_pinyin1.py。
README.md 說明拼音首字母＋助憶＋補碼的三鍵結構；
intro.txt 的「暗」an -> a 例子也顯示實際概念為拼音首字母。
type_pinyin1.py 目前 load_pinyin_cin 讀 pinyin.cin，
load_word_files 讀 word*.txt，再合併至同一 key2ph。
該檔是全拼測試程式，不能當作本規格已完成的三碼主音／副音引擎。
未來修改時應為正式單字與詞組保留獨立型別／索引及來源資訊，
避免合併後無法阻止副音洩漏成單字碼。
uniok_utf8.txt 是現有碼表資料入口之一；實作前須讀實際格式，
並檢查 type1.py、cuf1.py、mem2tksm.py 等實際使用鏈。
本次未全面審閱上述資料及程式，故不指定未查證行號或假造解析欄位。
pinyin.cin 可作讀音候選來源，但不能直接提供可靠詞組讀音或使用頻率。
word*.txt 是程式使用的載入模式，不代表目前根目錄已有這些詞組檔。
在確認現有詞組取碼規則之前，不自行發明兩字／三字／多字詞取碼公式；
可先完成資料驗證、讀音覆寫及獨立索引介面，
缺少 phrase_code_rule 時產生清楚錯誤，不能把全拼串或首字母串冒充正式詞組碼。
未來若採 Odin，使用 rune / []rune 處理字位置，三鍵用 [3]u8，
詞組碼用 string，條目用明確的 Character／Phrase 類型區分。
這是可移植資料設計，並非要求把現有 Python 程式改寫為 Odin。

# 8. 資料整理與相容性
先匯出原單字碼快照，建立字到正式碼的基準。
為多音字補齊讀音候選、主音依據與 confirmed 詞組讀音。
詞組異讀、專名、地名、兩岸讀音差異須明確記來源，不全域強制轉換。
繁簡字分別保留原字形，不自動合併；讀音資料不能覆蓋字形。
新增副音前後，逐字比較正式碼，預期變更數為零。
輸出主音缺漏、待確認詞組、讀音 ID 錯誤、正式碼碰碼、
詞組碼碰碼及跨索引同碼報告；不可靜默修正或丟資料。
若既有資料已不符合每字一碼要求，先列出問題與遷移方案，
不得把既有重複碼誤稱為本功能已保證無重碼。
資料產物記錄 schema_version、rule_version、來源版本與確定排序，
相同資料和規則必須得到相同產物；未來實作不得隨機選主音。

# 9. 驗收條件（供後續程式實作）
1. 每字恰好一組正式三碼；所有副音均未產生額外單字三碼。
2. 副音開關前後、加入詞組前後，單字索引內容完全相同。
3. 「重要／重複」「銀行」「音樂」使用經確認的指定讀音。
4. 副音在詞組任意位置及同字重複位置均能正確套用。
5. 不在明確收錄詞組內的副音不得泛化成其他詞組條目。
6. 同首字母但不同讀音資料保留，生成相同詞組碼時正確去重。
7. 停用副音只移除副音詞組來源，不移除仍有主音來源的同碼詞組。
8. 三鍵詞組不被誤分類為正式單字；跨索引同碼不互相覆蓋。
9. 無效讀音 ID、越界字位置、缺字、重複 rank、主音不一致會報錯。
10. UTF-8 多位元組與補充平面單碼點漢字索引正確。
11. 重建不改變既有正式碼；不能將示意碼或未知頻率當真實資料。
12. 副音功能完成與否由實際生成報告及驗證結果判定，
    本規格本身不宣稱現有程式已提供上述能力。

# 10. 給 AI coding agent 的最終提示
本次使用者要求是保存規格，後續實作請以本文件為需求依據。
核心句：單字主音固定三碼，副音只在指定詞組內生效。
不要把副音實作成單字的多組三碼，不要自動換主音，
不要把 odinime 的英文語義取碼套進本倉庫。
保留既有資料與碼表，新增功能前先確認實際格式及詞組取碼規則。
